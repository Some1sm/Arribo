## 2. Logic Chain

1. **Premise 1**: The synthetic 30-minute / fixed-interval schedules observed in Mataró Bus lines originate directly from `MATARO_LINE_SCHEDULES` in `src/mataroTracker.js` (lines 12–53) and its stepping loop in lines 775–811 and 821–853.
2. **Premise 2**: In contrast to Mataró Bus, the other major interurban trackers (`src/corridorTracker.js`, `src/maresmeTracker.js`, `src/cataloniaTracker.js`) already ingest authentic GTFS departure matrices or official operator timetable APIs (Moventis / Mou-te).
3. **Premise 3**: In `src/mataroTracker.js`, replacing `MATARO_LINE_SCHEDULES` with complete, authoritative departure time matrices (for L1 through L8 across weekdays, Saturdays, and Sundays/holidays) and calling `scheduleSynthesizer.synthesizeDeparturesFromBaseTimes` directly eliminates all artificial uniform stepping.
4. **Premise 4**: For Line 8, encoding the authentic CTSA timetable (such as Saturday/Sunday afternoon-only service starting at 14:04 for Route 11 and 14:45 for Route 12) guarantees that morning requests return no false departures and afternoon queries return exact official passing times.
5. **Premise 5**: Enhancing `src/core/schedule/scheduleSynthesizer.js` to natively support multi-calendar scheduled matrices, seamless real-time SIRI to scheduled transition, and next-morning resumption ensures that all trackers adhere to the canonical schema without breaking existing test suites.

## 3. Caveats

1. **AMB Headway Modulo**: In `src/ambTracker.js`, real-time delay matching uses a modulo formula because AMB real-time API provides estimated minutes without attaching the GTFS static trip ID. This is localized to AMB and does not affect Mataró Bus or C-10.
2. **Topographic Run Times**: Stop travel times in `src/mataroTracker.js` are computed via cumulative road distance (`estimateStopTravelTimes`). In high-gradient sectors (e.g. upper Cerdanyola or Cirera), actual bus speeds vary slightly by traffic conditions; however, Haversine-based distance with 25s dwell time provides a realistic physical passing schedule.
3. **Read-Only Scope**: In accordance with the explorer role, no source files outside the `.agents/explorer_survey_trackers/` directory were modified.

## 4. Conclusion

The root cause of synthetic schedule gaps is completely identified and localized. Eliminating synthetic headways requires:
1. Encoding the complete authoritative departure time matrices for all 8 Mataró urban lines (L1–L8) across Weekdays, Saturdays, and Sundays in `src/mataroTracker.js` (or a dedicated static data module).
2. Updating `src/mataroTracker.js:getStopDepartures()` and `getTargetStopETA()` to feed these matrices into `scheduleSynthesizer.js`, replacing the `depSec += headwaySec` loop.
3. Enhancing `src/core/schedule/scheduleSynthesizer.js` to handle exact scheduled departure matrices, seamless live-to-scheduled transitions, and authentic next-morning first-trip resumption.
4. Adding a dedicated test suite (`test/mataro_timetable_test.js`) asserting non-uniform timetable sequences and verified first-service times across all 8 lines.
